# 12. 生产部署方案（执行系统试运行）

> 创建：2026-08-07
> 目标环境：部门内一台 Win10 64 位主机的 Docker 容器；同机（或另一台常驻
> Windows 主机）运行 Windows Bridge。
> **传输决策：全链路保持 HTTP，不启用 HTTPS**（用户 2026-08-07 确认，长期有效）。
> 开放范围：仅 4 个工作流——再生纤根数法、再生纤面积法、电镜纤维微观形貌、
> 纸/纸板和纸浆纤维鉴别分析 GB/T 4688-2020 定性。

## 1. 部署拓扑

```text
Win10 64 位主机
├── Docker（postgres / backend / execution-worker / frontend，:80 HTTP）
│     └── CIFS 只读卷 //192.168.105.82/材料检测中心 → /data/execution-source
└── Windows Bridge（Textile Execution Bridge 安装包，C:\TextileExecutionBridge）
      ├── 写入桥（计划任务，交互会话）→ Writer → 旧系统 Oracle / fibrecheckfile$
      └── 快照桥（计划任务）→ 只读 Oracle → execution_task_snapshot_cache
```

- 再生纤两个流程为纯只读（索引→读结果→人工选择），不触碰旧系统；
  `AREA_ENABLED=false`，不构建/启动 area-infer。
- 电镜与纸类流程写旧系统，必须走“外部操作→人工批准→Windows Bridge→回执”链；
  全局写入并发固定 1，同账号/同样品族串行。
- 桥与容器同机部署时，`execution_staging` 直接映射宿主机
  `EXECUTION_RUNTIME_HOST_PATH` 目录，无需额外同步层。

## 2. 服务端启动

仓库根 `textile-device-monitor/` 下：

```bash
docker compose --env-file <生产.env> \
  -f docker-compose.yml \
  -f docker-compose.execution.yml \
  -f ../.tmp/execution-system-local-runtime/docker-compose.production.yml \
  up -d --build postgres backend execution-worker frontend
```

`docker-compose.production.yml` 只做三件事：postgres 数据落宿主机目录、
backend/worker 挂 SimSun 字体、其余沿用主 compose（其默认
`EXECUTION_SOURCE_ROOT=/data/execution-source/10特纤/02-检验` 与 CIFS 卷
定义已满足生产）。

## 3. 生产 .env 清单（Git 外，管理员维护）

```text
APP_ENV=production
WEB_TRANSPORT=http
PUBLIC_HOSTNAME=<主机IP或主机名>
PUBLIC_ORIGIN=http://<主机IP或主机名>
EXECUTION_COOKIE_SECURE=false          # HTTP 下必须 false
FRONTEND_HTTP_PORT=80

POSTGRES_DB=...
POSTGRES_USER=...
POSTGRES_PASSWORD=<强口令>
POSTGRES_DATA_HOST_PATH=D:\textile-monitor\postgres-data

SECRET_KEY=<随机>
EXECUTION_SESSION_SECRET=<随机>
EXECUTION_CREDENTIAL_KEY=<随机并永久固定；变更会使已存旧系统凭据不可读>

EXECUTION_BRIDGE_ENABLED=true
EXECUTION_BRIDGE_TOKEN=<与桥 config\bridge.env 相同>
EXECUTION_LEGACY_SPECIAL_WOOL_WRITE_ENABLED=true
EXECUTION_LEGACY_MICROSCOPY_FINAL_ENTRY_ENABLED=true

EXECUTION_FONTS_HOST_PATH=D:\textile-monitor\fonts   # 内含 simsun.ttc（来自已授权 Windows）
EXECUTION_RUNTIME_HOST_PATH=D:\textile-monitor\runtime\execution-runtime
EXECUTION_PUBLISH_HOST_PATH=D:\textile-monitor\runtime\execution-publish
AREA_MODEL_HOST_PATH=D:\textile-monitor\runtime\area-models      # 占位即可
AREA_TEMPLATE_HOST_PATH=D:\textile-monitor\runtime\area-templates

SMB_USER_A=... / SMB_PASS_A=...    # //192.168.105.66 卷（主 compose 需要）
SMB_USER_B=... / SMB_PASS_B=...    # //192.168.105.82 执行源卷

# 仅首次引导使用，管理员创建后立即移除并重启 backend/worker：
# EXECUTION_BOOTSTRAP_ADMIN_USERNAME=...
# EXECUTION_BOOTSTRAP_ADMIN_PASSWORD=<强口令>
```

`APP_ENV=production` 触发弱口令强制校验（`config.py`），空/弱值无法启动。

## 4. 初始化与冒烟

初始化脚本（幂等，不含凭据）：

```bash
bash ../.tmp/execution-system-local-runtime/production-bootstrap.sh
```

它完成：禁用 `special-wool-source-selection`、`hemp-cotton-source-selection`、
`system-controlled-xlsx-write-test`（并防御性确认 `electron-source-selection`
禁用）；容器内 `fc-match 宋体` 检查；存储根列表。

随后人工步骤：创建检验员账号 → 登记 legacy_inspection 凭据 →
Windows Bridge 装机自检 → 用 26W006701 验证快照刷新命中
“纸、纸板和纸浆纤维鉴别分析 / GB/T 4688-2020”。

冒烟顺序（先只读后写入）：

1. 再生纤根数法/面积法：查找→读结果→人工选择（纯只读）；
2. 任务快照桥只读刷新（不写旧系统）；
3. 电镜微观形貌：选图→生成原始记录（只写 staging）；
4. 电镜上传→复核→登记/校对（真实写入，批准链）；
5. 纸类定性：读 W32→上传→复核→登记只保存（单位规则：
   独立 100/100.0 → `%`，其余空）。

## 5. Windows Bridge 安装包

统一由 `textile-device-monitor/packaging/windows-bridge/` 构建（详见其 README）：

- 构建机执行 `Build-BridgePackage.ps1`：收集 Python 工具、两个 Writer
  （SHA-256 钉值校验 + 补 x86 Oracle.DataAccess.dll）、冻结 FibreCheck
  客户端、x64 Instant Client、CPython 运行时、probe 离线依赖、ops/config，
  再调 Inno Setup 输出单文件安装包；
- 生产机安装后：`config\BridgeConfig.psd1`（非机密）+ `config\bridge.env`
  （机密，ACL 收紧）→ `Test-BridgeInstallation.ps1` →
  `Register-BridgeScheduledTasks.ps1 -UserName <操作员>`；
- 写入桥任务“仅当用户登录时运行”（FinalEntry COM Excel 需交互会话），
  主机重启后需该用户登录；
- 升级 = 覆盖安装；`config\`、`work\` 不受卸载影响；Writer 钉值随包更新。

## 6. 备份与回滚

- 备份对象：`POSTGRES_DATA_HOST_PATH`（或 pg_dump）、`.env`、
  `EXECUTION_RUNTIME_HOST_PATH` / `EXECUTION_PUBLISH_HOST_PATH`、
  桥机 `config\` 目录；共享盘源文件本身只读不涉及。
- 回滚：容器镜像按 Git 提交重建；数据库迁移到 0006 为止均向后兼容，
  回滚代码版本前先 pg_dump。
- 旧系统侧回滚不自动执行：任何写入异常进入 `reconciliation_required`，
  只读对账后人工声明终局，绝不自动重试。

## 7. 风险与边界

- Win10 Docker Desktop 需保持登录会话（CIFS 卷与桥计划任务都依赖登录态）；
  建议固定 IP/主机名，`PUBLIC_ORIGIN` 与之保持一致。
- HTTP 明文仅限内网；桥令牌、凭据因此尤其依赖主机与共享盘 ACL 保护。
- Oracle 11g 必须用 Thick 模式（包内 x64 IC 19.31）；主配置账号被拒时用
  `WebService.dll.config:PanYuJianWu` + 备用地址 `192.168.105.106/orcl`。
- 微观形貌记录正确性强依赖容器内 SimSun；无宋体环境不要调
  `MICROSCOPY_BIFF_EXCEL_X_SCALE`，排版约束见 `11_原始记录排版约束格式.md`。
- 快照桥每次领取只处理一个排队刷新请求，靠轮询消化；批量刷新时属正常。
