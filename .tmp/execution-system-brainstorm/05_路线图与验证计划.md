# 05. 路线图与验证计划

> 状态：首版实施中
> 最后更新：2026-07-25
> 当前约束：基础框架可以开发；生产检务系统写入仍需内网、测试账号和测试单后另行授权

## 0. 当前首版实施顺序

1. Alembic 现有结构基线、执行系统迁移、生产密钥门禁与独立认证；
2. 工作流 Schema、节点注册表、完整设计器、草稿冲突与不可变发布；
3. PostgreSQL 租约 Worker、条件/并行/汇合、人工任务、事件、Outbox 与 SSE；
4. 数据根别名、后台索引、电镜采集分组、制品血缘和受控写入；
5. 特种毛、麻棉、电镜三个发现流程及再生纤缺失状态；
6. 后端、前端、迁移、Compose 和真实页面门禁，不构建 Area Infer。

当前代码与测试结果持续记录在 `07_首版实现与验收记录.md`。

## 1. 推进原则

1. 公共框架与可视化设计器同步建设，但未知业务规则不写死在节点中。
2. 先证明节点契约、恢复和文件安全正确，再扩大到具体检测计算。
3. 先影子运行、生成副本，再连接生产检务系统。
4. 先接新网页系统测试环境，再处理旧桌面系统。
5. 所有不可逆动作都在具备预检查、幂等和回执后开放。
6. 每个阶段都使用真实 Excel 和真实业务人员验收。

## 2. P0：业务取证与规则冻结

### 目标

把“棉和再生纤维素纤维物理法定量”写成无歧义的业务说明。

### 需要收集

- 至少 5～10 份真实但可脱敏的原始记录；
- 单文件、多文件、复核通过、超阈值、第三人等案例；
- 模板的所有历史版本；
- 文件目录结构和命名样本；
- Excel 中编号、检验员、根数、面积、含量和备注的位置；
- 公式、宏、图片、打印设置、保护和外部链接情况；
- 阈值计算公式；
- 第三人结果的最终取值规则；
- 上传原始记录和录入报告结果的业务操作录像/截图；
- 微观形貌图片的目录与命名规则。

### 输出

- 业务泳道图；
- 字段字典；
- 模板版本矩阵；
- 复核/第三人决策表；
- 外部系统动作清单；
- 第一版节点输入输出草案；
- 真实验收案例集。

### 门禁

以下问题未回答前不进入正式开发：

- 复核比较精度；
- 第三人裁定规则；
- Excel 是否必须使用真实 Office 重算；
- 哪些外部步骤才算整单完成；
- 原始记录是否允许生成工作副本。

## 3. P1：领域模型和固定流程模拟

### 目标

不开发通用画布，先用 JSON/固定配置表达第一条流程，并验证模型是否覆盖业务。

### 工作内容

- 定义 `FileArtifact`；
- 定义结构化检测结果；
- 定义主检、复核、第三人提交；
- 定义最终结果；
- 定义人工任务；
- 定义节点类型注册信息；
- 定义工作流 JSON Schema；
- 设计节点运行状态和恢复规则；
- 使用纸面或交互原型模拟完整执行。

### 验证问题

- 单文件是否能自然通过同一套接口？
- 多文件如何确定主单？
- 第三人等待能否跨天恢复？
- 并行输出的部分成功如何展示？
- 文件变化后如何处理？
- 工作流版本更新是否影响旧运行？

### 门禁

对至少 5 个真实案例进行桌面推演，不能依赖“特殊人工解释”才能走通。

## 4. P2：最小垂直切片（影子模式）

> 基础框架、文件发现流程和专用测试工作簿写入已授权开发；真实业务模板和检务提交尚未授权。

### 范围

1. 登录；
2. 输入/扫描检验编号；
3. 选择项目类型；
4. 查询一个配置根目录及一级子目录；
5. 默认查询最近 7 天并显示 6 个候选；
6. 异步识别 Excel 类型和提取摘要；
7. 选择一份或多份原始记录；
8. 自动或人工确定主单；
9. 补充缺失根数；
10. 在副本上完成 Excel 写入/合并/计算；
11. 读取主检和复核结果；
12. 阈值比较；
13. 超阈值时创建第三人任务；
14. 生成最终 Excel 和完整审计记录；
15. 用“人工确认已在检务系统完成”临时节点代替真实自动提交。

### 暂不包含

- 旧检务系统正式自动化；
- 新检务系统生产提交；
- 通用插件市场；
- 任意代码节点；
- 面向所有项目的通用设计器；
- 全自动最终提交。

### 关键验收

- 服务等待人工输入时重启，流程仍可继续；
- Windows Agent 执行中断，租约过期后可恢复；
- 重复点击不会产生两个结果文件；
- 原始文件始终不变；
- 选择后文件变化会阻止执行；
- 错误模板不会进入合并；
- 一个文件、多个文件和第三人分支均可完成；
- Excel 重新计算后的关键值经二次读取核对；
- 每次人工修改都有人员和理由；
- 可还原最终结果来自哪些文件、人员、模板和规则。

## 5. P3：通用工作流编辑能力

在节点契约稳定后再开发：

- 可视化画布；
- 端口类型检查；
- 节点配置表单；
- 条件和并行汇合；
- 子流程；
- 草稿、测试和发布；
- JSON 导入导出；
- 流程差异；
- 能力和凭据槽位绑定；
- 测试数据运行；
- 节点级重放。

## 6. P4：新网页检务系统测试对接

优先取证是否有正式 API。

阶段步骤：

1. 只读查询任务；
2. 在测试环境上传原始记录；
3. 查询回执并验证幂等；
4. 录入最终结果但不正式出证；
5. 处理登录失效、MFA 和超时；
6. 人工确认后开放小范围灰度；
7. 连续验证无重复提交后，才考虑自动确认。

## 7. P5：旧检务系统取证和连接器

前置条件：

- 内网；
- 测试账号；
- 可回滚的测试单；
- 固定版本旧客户端；
- 明确的授权范围。

取证顺序：

1. 系统已有导入/导出能力；
2. 官方或内部 WebService/API；
3. 已有 `fibrecheck_tools` 可以确认的只读业务接口；
4. 程序业务层调用；
5. 最后才是桌面 UI 自动化。

禁止：

- 未确认业务校验链时直接写生产数据库；
- 用屏幕固定坐标作为唯一定位；
- 无回执时无限重试；
- 测试过程覆盖真实生产记录。

## 8. P6：生产治理

- 凭据轮换；
- 角色与职责分离；
- 审计导出；
- 节点和流程发布审批；
- Agent 升级和能力版本；
- 文件/制品保留策略；
- 失败任务值班和 SLA；
- 连接器健康监控；
- 业务指标；
- 备份和恢复演练；
- 回滚和修订流程。

## 9. 第一阶段建议指标

效率：

- 查找文件平均耗时；
- 每份单人工录入次数；
- 从面积识别完成到最终结果形成的时间；
- 检务系统重复录入减少量。

质量：

- 文件类型识别准确率；
- 模板不匹配拦截数；
- 重复提交拦截数；
- 人工修改率；
- 自动化后发现的结果差异。

稳定性：

- 节点成功率；
- 自动重试后恢复率；
- 人工任务平均等待时间；
- 外部系统 `needs_reconciliation` 数量；
- Agent 离线和租约恢复次数。

## 10. 下一轮头脑风暴建议议题

建议先完整讨论以下一组问题：

> “一份棉再定量任务从编号开始，实际可能出现哪些文件？主检、复核和第三人的文件如何区分？阈值和最终取值到底怎样计算？”

讨论时最好提供：

- 2～3 份脱敏 Excel；
- 一个正常通过案例；
- 一个触发第三人案例；
- 最终上传界面截图；
- 文件目录示意。

这组信息能直接修正领域模型、卡片摘要、人工任务和第一条固定流程。
