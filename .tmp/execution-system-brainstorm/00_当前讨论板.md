## 多人、多账号的确定方向

不在每位用户电脑上安装 FibreCheck 桌面自动化 Agent。采用：

```text
多人网页提交
  -> PostgreSQL 持久队列
  -> 一台集中式 Windows Bridge
  -> 每任务一个短生命周期 x86 .NET Framework Runner
  -> 使用该任务绑定的旧账号无界面登录并调用官方 DAL
```

- Bridge 可以先运行在当前 Parallels Windows 11，生产时再迁移到部门常驻
  Windows 主机；
- 不依赖 WPF 窗口焦点、交互桌面或每人安装；
- 用户提交可并发，实际旧系统写入首版全局并发固定为 1；
- 稳定验证后才考虑提高到 2～4；
- 同账号、完整样品号、前 9 位样品家族和目标文件始终串行；
- 每个 Runner 结束立即退出，隔离 `CurrentLoginedStaff`、ODP.NET 和静态状态；
- 远端副作用开始后结果未知时进入 `reconciliation_required`，绝不盲目重试。

完整、可随 Git 带到 Windows 的交接手册：

```text
textile-device-monitor/docs/legacy-fibrecheck-bridge-handoff.md
```

## 阶段 D 关键环境事实（2026-07-31 核验）

- 官方 DAL 链路要求 `FibreCheckWriter.exe.config` 带
  `<add name="bool" value="edmmapping number(1,0)"/>`（旧客户端
  `FibreCheck.exe.config` 同款），否则 ODP.NET 11.2.0.2 报 MappingException 2019；
- 32 位 ODAC 11.2.0.2.50 xcopy 包来自 `\\192.168.105.66\software\2-业务系统\ODAC`，
  本机复制到 `.tmp/odac32/`；本机 GAC_32 已有 4.112.2.50；
- 用户现行客户端：`C:\Users\lishuyang\Downloads\FibreCheck`；
- 演练后端：原生 uvicorn + worker + SQLite（便携 PG 因外网速度不足未下载，
  偏离已记录）；`.env` 在 `textile-device-monitor/backend/.env`（git 忽略）；
- 中文 Windows 控制台默认 GBK：任何解析工具进程 stdout 的消费方必须注意
  编码（Runner 已强制 UTF-8 输出）。

单一编号拆为：
