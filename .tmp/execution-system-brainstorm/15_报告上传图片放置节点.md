# 15. 报告上传图片放置节点

> 最后更新：2026-08-18
> 状态：已实现并随电镜两条流程发布；本地真实共享盘活体冒烟通过，
> 等待用户完整流程实测。

## 1. 需求与结论

电镜—纤维微观形貌 GB/T 36422-2018、电镜—纤维横截面 GB/T 36422-2018
两条流程在末尾（旧系统检验记录登记完成之后）新增“放置报告上传图片”
节点：把本次选中的全部图片写入

```text
\\192.168.105.82\公共交换文件\数据分析中心\3-报告上传图片\8-材料检测中心\1-微观形貌-GB T 36422\{检验编号}\
```

命名规则（2026-08-18 与用户确认）：

- 样品识别取**流程中人工确认的样品识别**（record-input，与写入 Z7/登记
  记录一致），不按图片二级目录分组，也不逐张询问；
- 同一运行内第一张图不带序号，其后从 1 递增：
  `{编号}-{样品识别}.bmp`、`{编号}-{样品识别}-1.bmp`……
  样品识别为空时退化为 `{编号}.bmp`、`{编号}-1.bmp`；
- 保留源图片后缀（索引侧已统一小写）；样品识别中的 Windows 非法文件名字符
  （`<>:"/\|?*` 及控制字符）替换为 `-`，结尾点/空格剔除；
- 编号文件夹不存在则创建；横截面流程与微观形貌**共用同一目标目录**；
- 写入前发现同名文件：暂停并询问“覆盖同名文件并放置 / 取消放置”，
  询问界面提供可一键复制的完整 Windows 路径；取消 = 不放置任何图片，
  流程正常结束（旧系统登记已完成，不受影响）。

## 2. 实现要点

- 节点类型复用 `human.input` + config 标记 `report_image_placement: true`
  （与 paper_existing_record_decision / paper_judgement 同一模式）：
  - 节点进入时（worker）计算放置计划（确定性命名 + 目标目录冲突检测）；
    **无冲突则立即写入并自动完成，零人工干预**；有冲突则计划随人工任务
    下发，表单仅 `placement_action`（覆盖/取消）；
  - 提交“覆盖”时按当前输入与当前文件系统**重建计划**再写入（不冻结旧
    计划），覆盖语义 = 目标文件夹中所有同名文件；
  - 无冲突路径写入用排他创建（`xb`）：写入瞬间出现同名文件则以
    `report_image_conflict_detected` 失败，重试节点即转为人工确认，
    绝不静默覆盖；
  - 回执含每个文件的大小与 SHA-256、覆盖清单、目标目录与展示路径。
- 路径管理分两层：
  - **流程设计可管理**：节点 config `target_directory`（根内相对子目录，
    设计器 JSON 可改，默认
    `数据分析中心/3-报告上传图片/8-材料检测中心/1-微观形貌-GB T 36422`）；
  - **部署侧**：新存储根 `report_upload_images`（write），容器路径由
    `EXECUTION_REPORT_IMAGE_ROOT`（默认 `/data/report-upload-images`）；
    冲突询问中展示的 UNC 前缀由 `EXECUTION_REPORT_IMAGE_DISPLAY_UNC`
    （默认 `\\192.168.105.82\公共交换文件`）——UNC 属于部署知识，且流程
    定义校验禁止绝对路径字符串，因此不进节点 config。
- 定义校验：`human.input` 新增 `target_root_id → write` 访问一致性检查；
  流程 root_slots 增加 `report_images: report_upload_images (write)`。
- 目录升级：定义构建器新增 `legacy_image_placement_contract` 开关重建
  引入本节点前的形状（微观形貌 `df00b313…`、横截面动态同构），两个流程
  的未修改兼容集合均登记该形状，存量库启动时自动追加版本：
  微观形貌 v4→v5、横截面 v2→v3。横截面流程经 `**kwargs` 透传同一切换。
- 模块：`backend/app/execution/report_image_placement.py`；引擎接线点：
  `execute_claimed_node` 人工分支自动完成/表单钩子，
  `_normalize_human_submission` 的 `human.input` 标记分支。
- 前端：`ReportImagePlacementPrompt.jsx`（目标路径 `copyable`、拟放置
  清单逐张标注“同名已存在/新增”），`HumanTaskCard` 在
  `nodeRun.input_data.placement_plan` 存在时渲染。

## 3. 挂载与凭据

- 主 compose 新增 CIFS 卷 `report_images_cifs`
  （`//192.168.105.82/公共交换文件`，**可写**），挂到 backend 与
  execution-worker 的 `/data/report-upload-images`。
- 凭据使用独立变量 `SMB_USER_C` / `SMB_PASS_C`：材料检测中心共享在本机
  可访客只读（local.env 的 SMB_USER_B 曾为占位符），但公共交换文件共享
  **拒绝匿名挂载**，必须是真实读写账号（已验证生产 server.env 的
  SMB_USER_B 账号可写，本机 local.env 的 SMB_USER_B/C 均已改为该账号）。
- 注意：Docker CIFS 卷会把创建时的凭据固化在卷配置里；改凭据后必须
  `docker volume rm` 旧卷（先删引用它的容器）再 up，否则继续用旧凭据。
- local 覆盖：`report-upload-images/` 本地可写测试目录；company-lan
  覆盖把该挂载切回真实 CIFS 卷。
