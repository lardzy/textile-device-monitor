# 09. 电镜—纤维微观形貌 GB/T 36422-2018 首版

> 最后更新：2026-08-03
> 状态：已实现“任务匹配 → 选图 → 原始记录生成 → 打印确认 → 旧系统上传/复核预检”；旧系统真实写入继续冻结。

## 1. 本轮范围

当前发布流程为：

```text
开始
→ 查找微观形貌图片
→ 人工选择图片结果
→ 准备任务单字段与样品名称候选
→ 人工确认样品名称、样品识别和按需判定
→ 生成并重读核对微观形貌原始记录
→ 下载与打印确认
→ 旧系统上传-特种毛-图片（仅预检）
→ 旧系统-特纤复核（仅预检）
→ 结束
```

旧系统两个节点已具备持久化协议和预检数据结构，但当前三层禁写：能力声明为
不可执行、后端拒绝批准、Bridge/Writer 拒绝领取和执行。尚未完成旧系统子记录
语义及复核联动实机证明前，不得开启真实写入。

## 2. 工作流匹配规则

专用节点类型为 `file.electron_microscopy_gbt36422@1`，数据根为
`electron_microscopy_records/2026-电镜`。推荐分数由以下条件逐项累加：

1. 数据根可用；
2. 顶层文件夹名包含完整检验编号；
3. 同一任务项目的名称属于 `纤维微观形貌` 或 `膜平面形貌`；
4. 同一任务项目的测试方法为 `GB/T 36422-2018`；
5. 用户选择“电镜”为优先类别时再加类别分。

四项业务条件全部命中才是 `full_match`。项目名称与测试方法不能从两个不同
项目拼接。`膜平面形貌` 纳入同标准子项，是 2026-08-03 经真实任务单核验后由
用户明确确认的业务口径。

## 3. 索引与任务单缓存

- 电镜索引由后台递归扫描全部嵌套层级；用户搜索只查询 PostgreSQL 索引，
  不即时遍历共享盘。这样既覆盖现有“编号文件夹/部位/图片”结构，也不会静默
  漏掉未来更深层的项目目录。
- 图片后缀大小写不敏感，支持 BMP、GIF、JPEG/JPG、PNG、TIF/TIFF、WEBP。
- 旧系统任务单使用独立的 `execution_task_snapshot_cache` 缓存；编号统一转大写。
- 正常快照默认 15 分钟有效；过期时允许先返回旧快照并排队刷新；失败默认
  60 秒后重试。合同评审修改任务信息后，最迟在缓存到期或管理员主动刷新时更新。
- 推荐 API 不直接查询 Oracle。独立 Windows 只读 Bridge 领取待刷新编号，探针
  仅执行 `Task` 和 `Task_CheckItem` 两个参数化 SELECT，确认只读事务后统一回滚。
- Bridge 租约默认 180 秒，单次探针 90 秒超时；领取使用一次性
  `claim_token + bridge_id`，避免重复结果覆盖。

## 4. 图片人工任务

- 先列出全部匹配顶层文件夹，可多选；多选后把图片合并到同一选择界面。
- 至少选 1 张、最多选 10 张；可指定主图。
- 卡片展示缩略图、文件名、来源文件夹和二级部位；支持大图、上一张和下一张。
- 后端重新校验文件夹 ID、图片 ID、候选归属、去重、1～10 上限、索引指纹和
  真实文件状态，不能只依赖前端校验。
- 预览接口只读取电镜根中的已索引图片，并在返回前复核扩展名、大小和指纹。

## 5. 原始记录生成

- 模板固定为 `gbt36422-2018-microscopy-original-record-v1.xls`，SHA-256 为
  `d2b70e114cb85c89e4961ba2acb1b0cb451656f7a12b5dd5bdbacba1d50f88ba`。
- 任务快照已升级为 schema v2，分别保留 `sample_names`；样品名称候选使用
  `sample-name-v1`，先保留按业务逗号拆分的完整名称，再追加固定版本 jieba 分词，
  分词不可用时采用确定性回退。
- 样品识别支持中文逗号、英文逗号和顿号；0 项不询问、1 项自动选用、多项由
  用户选择。只有任务项目 `give_judgement` 非空/非 0 时才显示判定依据和判定。
- 写入工作表“微观形貌”：B2 检验编号、B3 样品名称、L3 样品识别；需判否时
  写 B33 和 I34。I33、B34、B35 在本轮保持空白。
- 1～10 张图片在 A4:L32 的 21.6 cm × 11.7 cm 范围内等比例最大化布局。
  单图必须贴满至少一条边并在另一方向居中，不裁剪、不拉伸；多图自适应网格。
- LibreOffice/UNO 保存后重新打开，核对 OLE 文件头、单元格、图片数量、位置、
  尺寸、边界及默认打印区域 `微观形貌!A1:L37`；单图还会按 `.xls` 坐标取整
  容差再次核对宽高比、限制轴贴边和另一轴居中，再登记带 SHA-256 的制品。
- 生成文件名固定包含“图片”：`{编号}-图片-纤维微观形貌原始记录.xls`，满足
  旧系统按文件名判定 `FileType.图片` 的既有逻辑。

## 6. 旧系统上传与复核边界

- 上传预检固定业务字段：纤维类别“图片”、检验方式空、检测项目“图片”、份数 1；
  检验员取当前执行系统用户显示名，不接受前端覆盖。
- 上传只接受本次运行、服务端登记且 SHA-256/大小/路径均复核通过的 `.xls` 制品。
- 目标编号按原号、`-1`、`-2` 在本系统围栏内暂定；旧系统远端占用查询尚未接入，
  因而该编号不能在启用写入前视为最终分配。
- 复核节点只能引用同一运行中已完成并回读核对的图片上传操作，使用独立阶段和
  副作用边界；当前上传不可完成，所以正式流程会停在上传预检，不会提前复核。
- 待实机证明：`OriginalDataPictureFile + CheckItemID` 子记录创建/回读，以及复核
  对主记录、细度/定量子记录和 `CheckItemID` 的联动更新。
