### 存活、就绪与执行保护

- `/health/live` 只表达 API 进程存活。
- `/health/ready` 同时检查数据库、Alembic 版本、Worker 心跳、staging 可写性和
  publish 可写性；兼容端点 `/health` 与就绪语义一致。
- 本地实际启动后，`/health/live` 和 `/health/ready` 均返回 `200`，Worker
  独立健康检查通过。
- 节点租约过期最多重试 5 次，达到上限后明确结束节点和运行，不再无限领取。
- 租约耗尽扫描在锁定运行和节点后重新检查租约令牌、到期时间与尝试次数，避免
  与 Worker 续期竞态时误判失败。
- 发布节点已经开始执行时，普通节点失败或人工任务驳回会进入
  `failure_pending`：先取消仍可撤销的兄弟节点和人工任务，再等待发布落库
  成功、失败或生成待对账信息，最后进入 `failed`。
- 用户取消运行时，如仍有发布动作在途则进入 `cancel_pending`，等待所有历史
  遗留的活动发布节点形成持久化结果后再结束，避免把“已发布”误报成“已取消且
  无副作用”。
- 新发布的工作流最多允许一个 `artifact.publish` 节点，从模型层面减少多目标
  发布时难以判定的部分成功状态。
- 公共 copy/write/verify/publish API 只允许操作实际已到达的节点；请求中的
  mutation、源文件、写入内容、工作副本和目标必须与不可变运行快照解析结果
  一致。发布必须关联已完成且由同一人领取/提交的 `human.confirm`，并精确匹配
  核对阶段生成的 `approval_context`。
- 发布节点和数据库栅栏在物理复制前提交；重复发布、发布中取消及 Worker/API
  竞争由同一锁顺序收敛，最终只允许一份物理文件和一条发布回执。
- 执行测试全部改用与生产一致的 `autoflush=False`。这曾真实暴露出“开始节点
  完成后，边决策仍未刷入数据库，后继节点保持等待”的停滞问题；当前已在边解析、
  激活级联、人工任务完成和制品状态转换处加入显式 flush，并完成全套回归。

### 领域模块

后端 `app/execution/` 按职责分离为：

- `models.py`：账号、权限、流程、运行、人工任务、索引、制品、变更和审计；
- `registry.py` / `validation.py`：版本化节点契约和无环 DAG 校验；
- `catalog.py`：默认角色、分类、流程、草稿与发布版本；
- `engine.py` / `worker.py`：租约领取、执行、恢复、重试和人工任务；
- `persistence.py` / `indexing.py`：数据根和数据库文件索引；
- `storage.py`：`root_id + relative_path` 安全网关；
- `mutations.py` / `mutation_runtime.py`：工作副本、写入、核对和发布；
- `excel_runtime.py`：Excel 类型识别和摘要读取；
- `events.py`：运行事件、事务 Outbox 和审计。

- 左侧“设备监控”后新增“执行系统”。
- `/execution` 使用独立登录，不改变其它页面和设备上报接口。
- 流程目录保留 URL 编号、多类别筛选、分类卡片和运行能力状态。
- `/execution/runs/:runId` 为左侧输入/人工任务、中间执行路径、右侧输出/警告/事件的三栏工作台。
- `/execution/admin/workflows/:workflowId` 提供节点拖放、整图连线、节点配置、变量、条件、汇合、校验、测试、发布、版本和 JSON 导入导出。
- 设计器会即时检查 JSON 字段，存在非法内容时阻止自动保存/发布；离开页面、

容器只认识下列别名，不接受工作流提供的绝对路径：

| root_id | 宿主目录下子目录 | 类别 | 权限 |
|---|---|---|---|
| `special_wool_records` | `2026-特种毛` | 特种毛 | 只读 |
| `regenerated_fiber_records` | `2026-再生纤` | 再生纤 | 只读；当前样本缺失 |
| `hemp_cotton_records` | `2026-麻棉` | 麻棉 | 只读 |
| `electron_microscopy_records` | `2026-电镜` | 电镜 | 只读 |
| `execution_staging` | 独立运行卷 | 工作副本 | 可写，不发布 |
| `execution_publish` | 独立发布卷 | 最终制品 | 可写、可发布 |

生产环境先把 SMB 共享挂载到 Docker 宿主机，再通过
`EXECUTION_SOURCE_HOST_PATH` 只读映射到容器。工作流 JSON 不保存
`smb://192.168.105.82/...` 或任何宿主机绝对路径。

索引查询只读数据库，不在请求线程遍历共享目录。后台 Worker 定期增量刷新，
默认忽略 `.recycle`、`旧`、Office 临时文件和符号链接。公共根目录和刷新接口
只暴露 `read` 根，拒绝索引 staging/publish 根；刷新深度限制为当前目录及一
级子目录。电镜按同目录同名 `.SIF + .bmp + .txt` 聚合。

## 3. 写入状态机

```text
源制品指纹
  → 变更预检
  → staging 工作副本
  → 版本化字段写入
  → 保存后重读核对
  → 人工确认
  → publish 根冲突检查
  → 原子发布
  → 制品、血缘、哈希和回执
```

- `mutation_id` 是幂等键；数据库唯一约束是多 Worker 最终仲裁。
- 受控写入既可由 DAG 节点推进，也可通过同一套运行时服务的分阶段公共 API
  推进；变更计划会在物理复制前持久化并 `flush`，即使复制失败也保留失败状态
  和恢复依据。
- 发布请求必须携带核对阶段生成的完整 `approval_context`，并绑定运行、源文件
  指纹、字段变更、目标根和目标路径；每个阶段写入审计、运行事件和 Outbox。
- 工作流版本的能力与运行能力均为不可变快照，管理员后续修改草稿或流程卡片
  能力不会扩大已发布版本和已启动运行的文件权限。
- 默认拒绝同名目标，不覆盖源文件或已有发布文件。
- `.xlsx` 支持结构化单元格写入。
- `.xls/.xlsm` 等格式若无法证明公式、宏、图片和格式完整，返回
  `excel_desktop_capability_required`，不静默转换。
- `.xls/.xlsm` 及其它高保真复杂模板的正式写入必须由后续 Windows Agent
  调用真实 Microsoft Excel Desktop 完成，Docker 内适配器不冒充该能力。
- 新、旧检务系统外部连接器仍为禁用占位节点；在获得内网、测试账号和测试单
  以前不可发布、不可产生真实外部副作用。
- 在线制品预览只允许固定栅格图片类型，拒绝内联 SVG；OOXML 工作簿在
  `openpyxl` 解析前检查条目数、解压体积、单条目大小、加密标志和异常压缩比。
- source、staging、publish 的容器路径及宿主 bind path 必须两两分离，不得
  相同、嵌套或通过符号链接/同一 inode 形成别名。

所有写请求在登录后校验 `X-CSRF-Token`；会话 Cookie 为 HttpOnly、
SameSite=Strict，可撤销。凭据接口只返回掩码，不返回明文。

### 6.1 旧 FibreCheck“特纤管理—检验”静态逆向结论

- 目标界面和业务类位于 `OriRecord.dll`：
  `SpecialWoolSearchUI`、`SpecialWoolAddUI`、`SpecialWoolDAL`。其中
  `SpecialWoolDAL.SaveSpecialWoolManage(...)` 是公开方法，但运行依赖 Windows
  x86、.NET Framework 4.0、32 位 ODP.NET、完整安装目录、内网 Oracle/文件
  服务器以及旧客户端已经初始化的登录态，不能从 Docker/Linux 直接加载。
- 根数法保存字段已经定位：`SampleNo`、`FibreSort=棉再生纤`、
  `CheckWay=定量`、`CheckUser1`、`CheckUserItem1=棉再生纤定量-根数法`、
  `CheckUserNumber1=1`。Excel 的 `I8` 是中文姓名，落库前还必须通过 `User`
  表唯一解析为人员 GUID。
- 旧客户端先把原始记录复制到
  `OriginalData/Files/YYYY/M/D/SpecialWool`，再保存 `SpecialWoolManage`；
  随后的报告原始数据更新使用另一个上下文再次提交。因此“文件复制、主记录、
  报告数据”不是同一事务，失败或超时后绝不能直接重试。
- 当前旧定量解析器固定使用 NPOI HSSF 并读取 `分组统计` 工作表。真实
  `260187115` 根数法工作簿没有该工作表，因此必须先只读核对现有记录的
  `IsImmediacyPublish`、关联子表和附件状态，不能推断人工上传会触发即时解析。
- UI 的重复检查使用包含匹配，数据库模型未发现 `SampleNo` 唯一约束；
  `260187115-1` 又会按前 9 位关联到底单 `260187115`。执行系统必须另建稳定
  幂等键，并同时检查精确编号和前缀冲突。
- ~~当前环境可访问再生纤 SMB，但无法连接旧系统主 Oracle 地址，因此尚未完成
  `260187115` 数据库侧交叉验证。~~ 已于 2026-07-30 在 Windows 11 完成只读
  交叉验证，见第 6.2 节。
- 多账号并发场景不采用单桌面 UI Agent 作为主路径。当前优先验证集中式
