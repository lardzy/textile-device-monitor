# Excel 保存后的索引滞后修复

日期：2026-10-14。

## 故障及原因

纸浆运行 `3732d41c-0eb0-4144-83c8-8e26b5fa691c`（编号 `26W007204`，v14）在“选择原始记录与项目”失败，错误为 `file_candidate_stale`。该运行未进入上传、复核和登记，没有产生外部操作。

索引记录的文件大小为 82,944 字节；文件随后保存为 84,992 字节。批量读取已成功读取新内容“木浆、竹浆”，却把旧索引指纹继续交给选择节点。选择校验把正常的保存误认为读取后的再次修改。

故障文件当前 SHA256 与失败运行实际读取的内容一致：`55cbef121fb83970c5a6d27d2a0f30c76272cb911d2ea6ef25c004bd5dad04ac`。

## 实现

- `workbook.extract_batch` 在读前、读后检查文件身份、大小和修改时间，并核对读取字节数。文件稳定时，以实际读取后的属性生成新的候选信息；解析与 SHA256 使用同一份字节。
- 读取中变化的单个文件返回 `file_changed_during_read`，同批其他文件继续返回结果。
- 人工选择及唯一候选自动选择，比较“当前实际文件”和“候选所依据的文件指纹”。索引继续提供文件 ID、目录与路径身份，不再要求其缓存指纹或缺失标记已刷新。
- 读取后真正修改、文件不可读、目录或路径不符等情况仍拒绝选择。
- 原查询输出、索引记录及历史 Run 快照均不改写，不增加扫描等待或新的后台任务。

文件、内核和工作簿 Pack 分别升级为 `1.4.1`、`2.13.1`、`2.14.1`。合同版本不变，重新封存实现摘要。纸浆 v15、微观形貌 v10 保持当前草稿的业务定义及本地绑定，仅更新发布信息和执行依赖。

## 验证与部署

针对性回归覆盖 XLS/XLSX 保存后索引尚未刷新、保存时索引暂记缺失、读取中变化、读取后变化、索引先后刷新，以及纸浆真实 Worker 链路。故障 Excel 使用只读副本与原有旧索引属性，在隔离环境读取并选择。

已通过 44 项针对性回归、故障文件副本验证、662 项后端测试及 55 个子测试（4 项跳过）。实际后端和 Worker 使用独立内存数据库、只读原文件，也已通过旧索引属性下的读取与选择验证。发布后导出的纸浆和微观形貌 JSON 完整链路及故障副本共 4 项隔离验收通过，导出内容与仓库示例一致。

完整测试结果与实际部署状态见 [验证记录](verification/excel-index-freshness-20261014.json)。测试数据库、制品及模拟检务回执均在隔离环境；修复验收不创建生产 Run，不补发真实上传或登记。

已完成纸浆 v15、微观形貌 v10 发布，46 个 Worker 能力绑定可用，两个容器各 122 份应用源码/JSON 摘要与交付一致。现有 88 次运行、176 条外部操作和 104 份制品的记录及内容摘要保持一致。

部署前保存 PostgreSQL 备份、当前草稿和发布 JSON、现有记录及制品摘要。确认无在途任务后，备份并更新现有后端和 Worker 容器中的应用文件，重启服务并发布上述新版本。保留容器、数据卷、历史文件与运行记录；前端仅重新加载 Nginx 上游地址。镜像另外按现有 Compose 组合构建，容器保留原身份和基础运行环境。

历史失败运行保持原状态。重新从流程入口发起的任务使用新版本；不把旧运行改写为新快照，也不自动重试该运行。

本轮不改变新文件发现策略：尚未进入索引的全新路径仍需索引扫描发现。本修复处理已发现 Excel 在保存后，读取结果与索引缓存版本不同步的问题。
