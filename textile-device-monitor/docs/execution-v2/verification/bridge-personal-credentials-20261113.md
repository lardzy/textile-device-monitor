# Windows Bridge 1.3.2：每项任务使用发起人的检务凭据

## 交付行为

- 上传、复核、纸浆登记、Excel 登记及通用更正使用任务发起人在执行系统中配置的检务账号和密码。分组子运行继承父运行发起人，同一座 Bridge 可依次处理多个用户。
- Bridge 配置中心不再提供检务账号和密码输入项，首次启用也不再要求这两项。已有机器设置及启停状态保留，旧本地检务凭据不再参与登录。
- 个人口令只由已认证的领取接口返回；启动独立 Writer 前从任务数据中取出，口令通过该进程的环境传入。普通操作接口、审计、临时任务包、待回执和日志不保存口令。
- 无效个人凭据使对应任务明确失败，其他用户的队列继续。领取或回执响应中断沿用原恢复链路，不重新执行已运行的 Writer。
- 保留旧 Bridge 领取格式，便于先构建 Docker 再覆盖安装 1.3.2。当前 Worker 同时支持这次更新前已发布的兼容运行快照；不改写历史运行。

## 验证

- 后端联合回归：83 passed、1 skipped；唯一跳过项是需要 PostgreSQL 的测试。
- 独立 PostgreSQL：原并发套件 22 passed，个人凭据竞争 2 passed。覆盖不同账号同时领取、坏凭据排在队首、全局写入容量保持 1、无孤儿 attempt。业务库未用于测试。
- 写入桥：66 项通过；快照桥：21 项通过。覆盖双用户账号密码隔离、没有本地检务账号时启动、含中文/引号/等号的口令、任务包与日志不泄漏、回执恢复及口令与业务编号重叠时业务结果保持不变。
- 实际 Windows PowerShell：配置 32 项断言、运行控制、WinForms 配置窗口、只读连接检查通过。1.3.0/1.3.1 设置直接读取，移除旧本地检务凭据后仍可启用。
- 安装包重新解包与交付源文件比对一致，程序自检通过。Writer 二进制沿用已验证的 1.3.1，本轮未修改 C# Writer。
- 实际 EXE 安装验收 20 项通过、0 失败：1.3.1 覆盖升级、配置字节保持、领取请求使用 `use_task_credentials:true` 且不含 `account_name`、实际配置窗口移除重复字段、无本地检务凭据仍可启用和认证、停用状态重复安装及自检。结束后原测试机的安装、任务、注册、快捷方式和配置恢复；未克隆虚拟机。
- 本机沿用原 Compose 组合更新 backend、execution-worker、frontend；三服务健康，API `/health/ready` 和 Worker 健康检查通过。微观形貌自动发布 v14、纸浆 v18；数据库版本仍为 `0014_run_groups`，运行记录仍为完成 90、失败 12、取消 6。
- Pack 与 7 份分发示例检查通过；发布兼容检查覆盖上次与本次更新前的快照。
