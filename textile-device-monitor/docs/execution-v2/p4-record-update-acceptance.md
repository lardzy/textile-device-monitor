## 实际行为

- Writer 使用官方 `CurrencyItemRecordDAL.Save` 的更新分支，保留通用记录 ID、登记 ID、创建人和创建时间；明细 ID 按官方行为重建。之后调用 `CurrencyItemGenerateReportDataService.UpdateOriginalData` 重新生成原记录对应的报告投影。
- **官方更新方法会更新登记的校对人、校对时间和最后修改时间。** 回执返回实际读取到的这些字段，不沿用新增登记的“未校对”假设，也不额外要求人工校对。
- 在项目锁内、实际执行点读取并比较完整原记录；不重复解析来源工作簿。修改后重新读取业务值、关联身份和报告投影，后端还核对未编辑字段没有丢失。
- `content_fingerprint` 是内容观察值，仍不是 Oracle 原子行版本。项目锁协调本系统 Writer；旧桌面客户端不遵循这个锁。实际保存使用旧 DAL 的多步提交，不能宣称跨步骤事务或阻止所有人工竞态。与本次意图不符的读回结果不会被标记成功。
- 新 Bridge 显式宣告 `legacy_generic_check_record_update`；旧 Bridge 不会领取新版任务包。Kernel Pack **2.5.0**，Connector / Connector Pack **1.4.0**；Engine / 协议保持 **2.4.0 / 2.1**。没有改变冻结 P1 Worker。

## 自动核对与续办

Worker 对结果未知的独立更正操作发起既有只读 Bridge 查询；不会拿提交前缓存认定写入结果，也不会采信在中断前已经开始的读取。核对记录及决策进入操作审计，原失败尝试继续保留。

| 当前事实 | 自动处理 |
| --- | --- |
| 原记录身份、提交字段、未编辑字段及报告结果符合目标 | 补记完成；内容未变化时不宣称发生了远端修改 |
| 原记录完整指纹未变 | 有限重试同一更正操作；已取消则结束，不重新写入 |
| 原记录已按本次意图更正，报告投影仍是旧值或缺失 | 只重新生成投影，不再保存主记录或重新登记 |
| 其他字段被修改、记录缺失、报告出现第三组值、达到重试次数 | 保留围栏并显示已取得的记录与问题 |
| 只读连接暂时失败 | 最多自动发起三次读取；恢复后刷新记录可继续核对 |

最多三次写入尝试；取消后不自动重启写入。该策略目前覆盖首个独立更正契约，不宣称七种旧写入都已具备自动恢复，也不把“登记数增加”当作新增操作成功的证据。
