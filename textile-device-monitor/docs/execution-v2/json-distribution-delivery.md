# JSON 工作流与独立适配器交付

本轮沿用已经完成的 P2–P5 引擎，不增加队列或插件服务。按以下四批实施并提交。

| 批次 | 交付 | 验收重点 |
| --- | --- | --- |
| 1 | JSON 规则定义、运行快照、安装/共享模板目录 | 跨环境仅绑定资源；修改本地规则不改变已发布内容 |
| 2 | 数据转换、校验、Python 计算；业务映射配置化 | 同能力内的字段与规则变化只修改 JSON，保留文件底层实现 |
| 3 | Connector 统一服务入口、独立适配包发现 | API 与工作流共用契约、幂等和回执；新增包不改中心分派 |
| 4 | 配置体验与独立 JSON 样例、回放、回归 | 导出后在另一环境导入、执行、验证 |

模板随安装包发布到用户可访问目录，也可从已挂载局域网共享目录选择。JSON 携带逻辑目录、相对路径及内容摘要，不携带机器路径和模板二进制；本轮不实现 `.twr`。共享目录使用现有 StorageRoot/FileGateway。

Python 是受信任流程作者的纯计算节点，版本化输入输出约定、独立进程、受限模块与执行预算。外部系统调用仍由 Connector 承担。安装适配器是代码部署行为，JSON 不导入任意 Python 模块。

生产和真实检务写入验收单独记录；本地测试不能替代现场验收。阶段性提交不推送、不部署。

## 第一批完成

规则 slot 可内嵌 `definition`，迁移预览自动带走已配置规则；绑定时只解析逻辑目录并冻结完整内容。三个原生查询家族读取发布快照。旧 JSON 的本地规则绑定仍兼容。`GET /execution/v2/templates` 支持指定根与相对目录，返回可选择模板及摘要；默认模板发布到宿主机运行目录的 `templates/`，配置表单接入在第二、四批。

验证：39 项资源、设计器、领域节点、再生纤测试通过；Pack 和示例已重新封存。未部署或调用真实检务写入。
