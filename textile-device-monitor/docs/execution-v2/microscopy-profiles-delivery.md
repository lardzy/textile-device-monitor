# 微观形貌业务方案与分组执行

实施日期：2026-09-29。当前为实施记录，完成与验证结果在各阶段补充。

## 设计

- 沿用 `fiber-microscopy-v2` 的 Workflow ID，显示名称改为“微观形貌”。
- 业务方案是流程 JSON 内的固定参数，包含明确的项目编号和方法组合、记录标题、模板对应关系、共享子目录、命名和表单默认规则。Python 完整随 JSON 分发；发布和运行沿用既有不可变快照。
- 首批方案为 `5103.5 / GB/T 36422-2018` 和 `5103.05 / 按客户要求`。样品识别是任务分组，不是业务方案。
- 设计器集中编辑方案，模板资源仍使用现有模板选择、目录绑定和发布摘要冻结。
- 分组选图输出明确的组和图片顺序；通用顺序批处理节点复用同一版本的现有 Run、Worker、操作队列和重试机制。已经成功的组不重复运行。
- 父运行与组运行关联持久化；运行时不读取可变业务规则表，不调用按业务名称隐藏的应用函数。

## 实施顺序

1. 方案配置、可视化管理、只读匹配预览和原方案回归。
2. 通用分组选图、同版本顺序执行、分组状态与失败恢复。
3. 模板及真实任务核对、隔离全链路验证、容器更新与重新发布。

前一轮源目录曾返回 `Host is down`。源图片、远端采集模板和现有登记均须以本轮实际读取结果为准。隔离测试不作为真实写入证据。

## 第一阶段

已集中业务方案参数，设计器提供增删、复制、启停、图片数量/模板映射、公共模板排版编辑和调用当前 Python 的只读匹配预览。匹配严格使用项目编号与方法组合；别名仅用于说明，不绕过项目身份。

验证：后端方案、图像查询和原生选择 6 项通过；4 项真实 UNO 全链路用例留待容器验证。前端方案编辑与设计器 4 项通过。新增方案复制后默认停用，防止复制操作立即制造重叠匹配；用户可编辑后启用。新项目的模板映射核实前，随附方案暂存为停用配置。

本轮已重新读到源共享目录，`260221991` 下有 H/N/W 三组 BMP 及伴随文件。图片分组含义仍由操作人确认，不根据文件名前缀自动猜测样品识别。

## 第二阶段

- 新增 `human.group_select@1`：分组分别选图和排序，统一校验数量、来源和重复分配；不根据文件前缀推断部位。
- 新增 `flow.batch@1`：顺序创建同一冻结版本的组运行。复用现有队列、Worker 和外部操作；后续发布不影响已有任务。成功组保留，重试仅恢复失败组；父任务暂停、取消会传递到当前组，待外部操作收尾后才结束取消。
- `0014_run_groups` 仅增加父运行关联和组上下文。运行页显示各组进度、待办入口、失败重试及返回全部分组。
- 单个部位的文件冲突取消视为该组“未提交”，仍允许其他组继续；取消全部任务则不再开始后续组。
- 只读取得 `5103.05` 配置的四份真实模板，冻结各自采集映射摘要。1/2/3 张模板内容相同，4 张为另一文件；安装包保存两份唯一资产。显式写入可见项目名 `C7`，避免模板遗留标题。
- 国标方案支持 1/2/3/5/6/7/10 张；按客户要求支持 1/2/3/4 张。

阶段验证：后端定向回归 51 项通过、7 项 UNO 用例转容器验证；隔离 Worker/UNO 的两套 JSON、单组与三组、文件冲突取消共 8 条完整链路通过（检务回执模拟）。PostgreSQL 迁移 `0014 → 0013 → 0014` 及并发共 30 项通过，包含重复分发只建一个组。前端分组及运行工作台 16 项通过。完整回归与真实验收继续在下一阶段记录。

## 本次真实测试约定

用户确认 N＝正面、W＝反面、H＝横截面；指定正反面各 1 张 5k 倍，横截面 200 倍与 3k 倍各 1 张。本轮取 `N_q01.bmp`、`W_q02.bmp`、`H_q01.bmp`、`H_q07.bmp`，倍率已同时核对仪器 TXT 元数据和图片标注。此对应关系只用于本次操作，不写成通用业务匹配规则。

按客户要求方案的目标目录固定为：

```text
\\192.168.105.82\公共交换文件\数据分析中心\3-报告上传图片\8-材料检测中心\5-按客户要求图片-特纤
```

不额外追加编号子目录。文件名为 `260221991-样品识别-序号.bmp`，每个部位序号从 1 开始。JSON 参数中 `{sequence}` 从 1 开始；`{identity}` 在非空时包含前置连字符。旧方案的 `{index}` 保留首张不带序号、后续从 1 编号的规则。目录可使用 `{number}`，因此国标方案保留编号子目录。
