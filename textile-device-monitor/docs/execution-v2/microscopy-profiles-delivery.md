## 设计

- 沿用 `fiber-microscopy-v2` 的 Workflow ID，显示名称改为“微观形貌”。
- 业务方案是流程 JSON 内的固定参数，包含明确的项目编号和方法组合、记录标题、模板对应关系、共享子目录、命名和表单默认规则。Python 完整随 JSON 分发；发布和运行沿用既有不可变快照。
- 首批方案为 `5103.5 / GB/T 36422-2018` 和 `5103.05 / 按客户要求`。样品识别是任务分组，不是业务方案。
- 设计器集中编辑方案，模板资源仍使用现有模板选择、目录绑定和发布摘要冻结。
- 分组选图输出明确的组和图片顺序；通用顺序批处理节点复用同一版本的现有 Run、Worker、操作队列和重试机制。已经成功的组不重复运行。
- 父运行与组运行关联持久化；运行时不读取可变业务规则表，不调用按业务名称隐藏的应用函数。

## 旧客户端空引用修复

用户在“特种毛检验／特纤复核”双击记录时报告空引用异常。只读查询确认上述三条 `SpecialWoolManage` 的 `FilePath` 非空，而 `FileType` 为 NULL。旧客户端 `SpecialWoolAddUI.BindData` 在该条件下直接调用 `fileType.Split(',')`，未判空，能够解释这两个入口的打开失败。

遗漏发生在本应用：流程及数据库保存的操作摘要已包含 `business_fields.file_type=定量试验`，但 `public_external_operation` 的字段清单未包含它；Bridge 复用这个清单，Writer 收到缺失值后写成了 NULL。旧实现直接设置 `FileType=定量试验`，因此没有这个问题。原验收只证明上传、保存及回执链，并未覆盖旧客户端打开记录；把空值与同样缺失的预期比较，无法发现协议字段遗漏。

- 后端完整传递 `file_type`，增加通过真实接口和 Bridge 序列化的回归断言。
- Writer 在复制文件和任何数据库写入之前拒绝缺失或空白的文件类型，沿用现有必填协议，不增加人工批准。
- 已备份三条完整记录，在单个事务中仅补齐 `FileType`，逐字段比较仅此列改变；之后独立连接再次读取，三条均为“定量试验”。未删除、重传或新增业务记录，未改写运行快照和历史回执。
- 同源旧测试 `260191178-2`、`26W006824-2` 也发现该空字段；已询问是否一并补齐，当前仍保持原状。此项与本次三条的修复分开记录。
- 热修复后端定向 5 项通过；Windows 上传 Writer 27 项及编译产物包校验 6 项通过，覆盖字段缺失、NULL、空串、空白、正常值及旧合同兼容。

数据库修复已核实；“旧客户端双击打开成功”仍需用户现场复验，不能用后端成功状态代替。
