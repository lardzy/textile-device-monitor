## 使用方式

流程管理的“新建流程”进入 v2 设计器。可以选用九条内置业务组合，也可以从空白流程开始；步骤视图用于调整配置，展开画布用于拖动、连接和分支设置。节点配置、输入输出字段、端口和 Connector 操作选项均由安装的 NodeSpec/OperationSpec 提供。

编辑结果自动保存在当前浏览器。点击“准备发布”后，服务端计算契约依赖、能力和摘要，前端自动导入候选，进入现有发布页。选择根目录、匹配规则和个人检务账号后，“检查并发布”完成绑定与发布。没有资源槽的流程自动建立空绑定。账号只选择一次，只有一个可用账号时自动预选；不要求手填 credential ID、revision 或摘要。

从 Release 页选择“设计下一版本”创建新候选，原文档和运行快照保持不变。版本号可调整；占用 slug 的模板会建议新的标识。模板中的复杂步骤仍是普通节点，没有新增嵌套引擎或另一套执行队列。JSON 高级编辑保留，用于少量非日常设置。完整角色、资产和跨环境绑定界面仍单列交付。

## 实现

- `/execution/v2/designer/catalog`：原生节点、Connector 元数据、空白图和内置组合。
- `/execution/v2/designer/compile`：只生成可审阅候选，复用 Release 校验；自动解析准确依赖、计算能力及摘要。修改签名文档产生新的未签名候选。
- `core.start@2`、`core.end@2` 以原生契约读取流程输入输出；`native_p4` 的九条候选全部没有兼容节点。
- 当前注册表有 31 份原生契约、39 份历史兼容契约、7 个 Pack；完整能力文档为 80 个绑定/78 ready。Kernel 2.8.1、Files 1.1.1、Workbook 1.0.1、v1 Compat 2.1.4、Domain Records 1.1.0、Regenerated Fiber 1.0.0、Legacy Connector 1.6.0。
- v1 新建画布入口已从日常管理界面移除。v1 人工业务协议移入 `compatibility_human.py`，原生表单由统一协议处理；旧编辑/重试 API 仍供历史维护使用。

## 引用审计与退场

管理页“历史兼容引用”和 `tools/execution_v2_reference_audit.py` 使用同一审计服务。检查全库未归档草稿、可回滚发布版本、待发布 Release、运行快照、未结人工任务和外部操作。失败但可以重试的 Run 仍属于有效引用；完成和取消的 Run 保留为历史引用。

每次 Worker 心跳按有效引用过滤兼容能力，零有效引用的类型停止广告和日常精确调度。39 种兼容能力全无引用时只保留 41 个原生/Connector 具体绑定。回切恢复旧入口后，下一次心跳自动恢复所需能力；不删除历史数据，不降级 `enforced`，不回退数据库。已经有精确绑定的旧 Run 仍需要其对应冻结 Worker，新的 Worker 不冒充旧实现摘要。

本地验收证明“归档 → 旧 Run/待办继续 → 引用清空 → 能力退场 → 回切恢复”的规则。现场何时达到零引用由实际数据库决定；本批没有把生产旧节点全部删除或宣称已完成生产退场。

## 部署与回退

Compose 的新默认值为 `enforced + p2_publish`，已有环境变量可以覆盖；既有两项微观形貌/特纤写入开关默认启用，仍需配置个人账号及可用 Bridge。这是仓库配置变更，尚未部署。

1. 更新 API、Worker、前端和相应 Bridge，迁移数据库到 head；根据实际精确绑定保留旧 Worker。
2. 在验收环境选择模板、绑定资源，用现场文件和指定测试编号核查结果。账号、文件和模板以实际环境为准。
3. 发布新 ID/slug 的流程后通过接替面板切换入口；受控 Excel 流程继续为内部验收。检查引用审计，待旧任务收尾后能力自动退场。
4. 需要回退时使用接替回切或 Release 版本回滚，保持契约模式与数据库版本。

`.twr`、Release 自带 fixture 执行器和完整资源绑定界面不属于本轮 P5 完成口径，继续独立登记。
