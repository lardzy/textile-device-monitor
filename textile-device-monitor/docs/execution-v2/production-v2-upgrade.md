# 生产更新：拉取代码后直接构建

更新日期：2026-11-12。

在生产机打开 PowerShell，进入平时执行构建的内层项目目录（包含 `docker-compose.yml`），执行原来的两条命令：

```powershell
git pull
docker compose --env-file .env -f docker-compose.yml -f ../.tmp/execution-system-local-runtime/docker-compose.production.yml up -d --build
```

构建完成、服务启动后刷新网页即可使用。无需另外迁移、预演、比对摘要、填写部署参数或先登录触发初始化。沿用现场 `.env`、账号、凭据、共享目录和数据库；Windows Bridge 继续使用 1.3.0。

## 启动时自动完成的内容

- 更新数据库结构、准备模板与目录绑定。
- 部署并启用全部现行流程：**微观形貌**和**纸浆纤维鉴别**，同时更新可编辑草稿。
- 微观形貌包含**纤维微观形貌、纤维横截面、按客户要求**三个业务方案。横截面支持 1／2／3 张图片，使用对应 XLS 模板。
- 直接删除旧 9 条内置流程，以及它们的旧版本、运行、待办和关联操作记录，不保留旧入口、不迁移或备份这些旧数据。以后从“微观形貌”进入横截面检测，不再使用“电镜—纤维横截面 GB/T 36422-2018”旧入口。
- 同一更新只安装一次，之后重启不会重复发布，也不会覆盖在设计器里继续修改的内容。本机与生产机使用同一组随代码交付的流程。

生产 Compose 已固定当前执行模式，旧 `.env` 中遗留的 `legacy` 或 `p1_readonly` 不再影响更新。模板、目录和凭据的准备及绑定由启动程序完成，不需要手动打开发布页操作。

账号、凭据、目录配置和设备监控数据保留。启动同步不会替用户创建业务运行或重复上传。

如果还开着更新前的旧流程页，返回执行系统目录并刷新，选择“微观形貌”或“纸浆纤维鉴别”。
