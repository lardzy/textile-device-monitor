# 工作流简化第一批实施记录

日期：2026-09-17。基于 `feature/execution-system` / `3b5bf1b` 及工作区已有 P2 接替实现。本功能尚未在生产投入使用，本次按授权调整业务代码和 Bridge 打包配置；没有执行部署、真实检务写入、提交或推送。

## 已实现

| 位置 | 新行为 |
| --- | --- |
| 日常启动 | 目录已填写编号、流程只需编号时直接启动；有其它字段或缺少编号时在当前页抽屉补齐，不再跳转准备页再确认。独立启动 URL 保留，流程图折叠为按需查看 |
| 重复提交 | 两种入口复用同一个启动 API helper；进行中的点击合并，网络失败保留原幂等键，获得运行 ID 后清除；服务端原有幂等约束继续生效 |
| 电镜与截面 | 新默认定义移除 `print-confirm` 及关联等待，生成记录后直接上传；需要打印时下载结果文件。旧版本/旧 Run 的图不改写 |
| 纸纤维 | “已有登记处置、样品识别与判定”移到首次上传之前；取消时不上传、不复核。无需判定且样品识别只有一项时自动完成 |
| 源文件检查 | 准备时生成一次稳定副本并解析；自动交付不立即重复复核。根数法领取只读取实际内容摘要与长度，不再复制和解析 Excel；仅修改时间变化可以继续，真实字节变化仍阻止错用文件 |
| Bridge | 写入 Bridge 常驻，处理完一项立即领取下一项；每个 Writer 仍为独立进程。只读快照 Bridge 也连续消化积压任务。空闲轮询默认从 15 秒降为 2 秒 |
| Release 管理 | “导入并检查”合并内容预检和导入；“检查并发布”自动保存改变的绑定、执行预检并发布。检查失败直接展示问题；“仅检查”是可选操作，接替仍使用已有明确入口 |
| 耗时 | 复用数据库已有时间戳，在操作详情/API 的 `timing` 中显示排队、执行和合计秒数；未发生的阶段返回 `null`。不增加表、监控平台或额外请求 |
| 页面与文档 | 删除准备页旧三栏/步骤说明及无用样式；字段校验只显示首个问题。修正文档中逐次批准、批准倒计时、默认双人审批的过时描述 |

已有自动交付开关默认 `True`，本轮复用这条路径。明确关闭该开关的手动兼容路径仍复核来源；不会把内部 Excel 人工批准验收伪装为自动批准。

保留的检查服务于具体正确性：目标样品/项目身份、真实内容是否变化、重复提交和写后结果。账号与权限沿用原有实现，没有增加审批角色或部署服务。

## 版本与配置

- Engine `2.1.1`；Kernel Pack `2.1.2`；`legacy_fibrecheck.v1-compat` `1.0.1`。源文件处理实现改变，按实际资源重算 Pack 摘要。
- 当前契约快照中 39 个旧节点的注册事实未改变；三个业务默认定义更新。三个 v2 示例依赖同步更新；冻结的 P1 快照保持原样。
- 默认目录初始化只升级识别出的系统原始定义：电镜、截面和纸纤维原版本及运行快照保留；用户自定义、已归档、待接替流程继续按 P2 规则处理。
- 无新增数据库迁移；本轮仍使用 P2 的 `0010_workflow_replacement`。
- 新 Windows 包使用 `BridgeConfig.psd1: PollSeconds=2`。已有安装配置不会自动覆盖，需要改该项后重启 Bridge。协调进程退出后的 5 秒重启退避只用于退出/故障，不再插入正常任务之间。
- 代码和包版本更新需要随应用/Worker/Windows 包部署后生效。本轮没有修改已运行服务或真实检务数据。

## 本地验证

- 后端：683 项通过、115 个子用例通过；5 项/模块按环境跳过。宿主机缺少 UNO 的 1 项在已有 LibreOffice Docker 镜像中独立补测通过。
- PostgreSQL：24 项通过，覆盖操作并发、接替、创建 Run、版本/revision 变化和回切。
- 两个 Bridge：写入 45 项、只读快照 18 项通过；验证连续两项不睡眠、空闲等待 2 秒、`--once` 仍只处理一项。
- 前端：Node 18 项、Vitest 137 项（25 个文件）通过，生产构建通过；覆盖直接启动、当前页补齐、重复点击、网络重试幂等、归档期间启动、绑定冲突和发布检查失败。构建保留原有大文件分块提示。
- 文件验证：领取阶段不再调用复制/Excel 解析；内容相同而时间改变可继续；相同长度和时间戳下改变字节仍被识别。
- 纸纤维 Worker 验证：必要判定先于外部操作；取消已有登记分支没有创建外部操作。
- 三份修改前的真实默认定义在内存数据库中重放升级：保留旧 WorkflowVersion 和 Run，重复初始化不增加版本，用户自定义草稿不被覆盖。
- 浏览器使用隔离 API、数据库和 Worker：目录直接启动、人工选择、实时更新至完成；同页额外字段表单和缺失字段提示；一次“导入并检查”生成 staged Release，选择绑定后一次“检查并发布”完成保存、预检和发布。

详细日志与机器可读记录位于 `.tmp/workflow-simplification-20260917/verification.json`。这些是本地/隔离环境验证，不是 Windows 实机或检务写入验收；没有以测试耗时冒充“已快于人工”。

## 后续保持原顺序

1. P3：先抽取再生纤面积法/根数法查询和结果读取服务，再拆电镜、纸纤维领域能力。
2. P4：统一查询/操作 API、精确记录更正、自动核对与续办，共用现有持久队列。当前 `/connector-operations` 和更正示例仍是设计，尚不可调用。
3. P5：NodeSpec 画布、常用业务组合和旧实现退场。

当前登记前的任务快照刷新、Writer 的当前状态核验和未知结果人工核对仍存在；它们应在连接器具备统一读取/恢复能力时合并，避免简单删掉后变成用户反复重跑。自动文件发布需要显式契约；`.twr`、Release 内置 fixture 执行器和完整绑定界面仍单独交付。
