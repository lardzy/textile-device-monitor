# Windows Bridge 1.3.1 现场操作

## 从当前版本更新

更新仍是两步，不需要手动迁移、清理回执文件或核对摘要。

1. 在生产机原来的 Compose 目录运行：

   ```powershell
   git pull
   docker compose --env-file .env -f docker-compose.yml -f ../.tmp/execution-system-local-runtime/docker-compose.production.yml up -d --build
   ```

2. 双击 `textile-execution-bridge-setup-1.3.1.exe`，覆盖安装。地址、账号、令牌、目录及原来的启停设置自动保留。操作员保持登录 Windows，安装结束后打开 **Bridge 配置中心 → 运行状态**，已启用的桥会自动恢复。

即使旧版显示“等待回执核对”，也可以直接安装新版。安装器会等待仍在工作的 Writer 退出，保留待回执记录；新版启动后自动交回服务端处理，继续领取其他任务。暂时断网会自动重试，不需要删除文件或重新上传。请先更新 Docker，再安装 Bridge。

## 本版变化

- 一条操作失败只影响这一条，不再停止整座写入桥。
- 遗留回执、回报连接中断会自动恢复；不会自动重复已可能执行的上传或登记。
- Excel 错误保留消息、HRESULT、堆栈和全部内层异常。运行详情的“旧系统上传”页可以展开和复制完整异常；v2 通用节点也显示此入口。
- 已请求取消且 Writer 已结束的运行可以收尾为已取消；尚不明确的远端结果保留在原操作中，便于查看。

## 首次部署

1. 运行安装包，打开开始菜单中的 **Textile Execution Bridge → Bridge 配置中心**。
2. 选择“与服务端同机”或“指定服务器”，填写执行暂存目录、纸浆目录、Bridge 令牌、检务与共享账号密码；选择平时登录桌面使用 Excel 的 Windows 操作员。点击“保存参数”“检查连接”。
3. 在“运行状态”启用快照桥和写入桥。启用后会处理已排队的任务，关闭配置窗口不会停止运行。

Excel 登记需要已安装可用的桌面 Excel，并由所选操作员登录 Windows。检查连接通过只说明本机、API 和目录检查通过；具体 Excel 异常会在执行记录中显示。

## 日常使用

修改设置后保存即可。当前任务用领取时的参数完成回报，下一项使用新参数。密码框留空保留原密码。换机可导出、导入普通参数，然后填写凭据并选择操作员。

程序位于 `C:\TextileExecutionBridge`；现场配置位于 `%ProgramData%\TextileExecutionBridge\config\settings.json`，升级保留。运行日志位于安装目录 `work\logs`；失败及恢复明细位于 `%ProgramData%\TextileExecutionBridge\runtime\receipts`。配置中心提供日志入口。
